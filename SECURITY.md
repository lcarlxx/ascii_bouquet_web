# Security Policy

## Supported versions

Only the current `main` branch is supported. This project is a static, client-side site; there are no long-lived release branches.

## Reporting a vulnerability

Please **do not open a public issue** for a live exploit.

- Use GitHub's private reporting: **Security → Report a vulnerability** on this repository.
- Or email the maintainer at the address on the repository owner's GitHub profile.

Include the URL or a minimal reproduction (a `?b=` share link is ideal), the browser used, and what you expected versus what happened. You can expect an acknowledgement within a few days. This is a hobby project, so there is no paid bounty — but fixes ship and credit is given if you want it.

## Scope

In scope:

- Cross-site scripting, HTML injection, or CSS injection through the `?b=` share link or the studio inputs.
- Denial of service against the visitor's own browser caused by a crafted share link (e.g. values that make the renderer allocate or loop unreasonably).
- Security-header regressions in `vercel.json` or the CSP `<meta>` tag.
- Dependency vulnerabilities that are reachable from the app.
- Supply-chain issues in the build.

Out of scope:

- The absence of authentication — there are no accounts, no server-side state, and nothing to protect.
- Content of a bouquet someone chooses to send you. Links are user-generated by design.
- Missing headers on a third-party host where the operator chose not to copy them.
- Self-XSS or issues that require a visitor to paste attacker code into their own console.
- Google Fonts availability or behaviour.
- Reports that amount to "the site is static and has no backend".

## Threat model

The deployable artefact is static HTML, CSS and JS. There is no server, database, session, secret, or user account. The only untrusted input is:

1. **The `?b=` query parameter** — a base64url-encoded settings diff, which anyone can craft.
2. **Typing in the studio** — the banner text and the colour hex fields.

Both are treated as hostile.

## Hardening already in place

**Share-link decoder** (`src/bouquet/defaults.js`):

- Payload capped at 4 KiB before decoding.
- Base64url → UTF-8 → JSON, then the result must be a plain object (arrays/scalars/`null` rejected).
- All numeric settings clamped to `NUMERIC_LIMITS`; integer settings rounded.
- Colours validated against `^#[0-9a-fA-F]{3,8}$`; palettes cannot change length.
- Banner message coerced to a string, control characters stripped, cut to 100 characters.
- Interdependent values normalised (`tulipCount ≤ flowerHeads`, size bounds ordered).
- `renderer` and `theme` validated against allow-lists.
- Any failure falls back to the defaults with a console warning — never to a partially applied state.

**Rendering:**

- ASCII frames are assembled with per-character escaping of `&`, `<`, `>`.
- No `dangerouslySetInnerHTML`, no user-controlled `innerHTML`, no `eval`/`new Function`.
- User-supplied colours pass through `sanitizeColor()` before reaching a style property.

**Browser policy:**

- CSP delivered as an HTTP header (with `frame-ancestors 'none'`) and mirrored in a `<meta>` tag.
- `script-src 'self'` — no inline scripts, no third-party scripts.
- HSTS, `nosniff`, `X-Frame-Options: DENY`, `strict-origin-when-cross-origin` referrer policy, restrictive `Permissions-Policy`, and COOP.

**Data handling:**

- No cookies, `localStorage`, `sessionStorage`, analytics, or telemetry.
- No network requests at runtime beyond the page bundle and Google Fonts CSS.
- Nothing is sent anywhere; the URL is the only state and it never leaves the visitor's machine unless they share it.

## Hardening guidelines for forks

- Keep `script-src 'self'`. If you add analytics you are choosing to weaken this — do it deliberately and document it.
- Keep `NUMERIC_LIMITS` in sync with any new setting. Every number that reaches `buildScene()` must be bounded.
- Do not interpolate user values into HTML strings.
- Never commit `.env` files or keys; `.gitignore` already covers `.env` and `.env.*`.
- Run `npm audit` and `npm run build` before publishing.
